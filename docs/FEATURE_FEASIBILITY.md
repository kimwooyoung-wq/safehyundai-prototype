# Feature Feasibility

SafeHyundai 프로토타입에서 무엇을 실제로 구현할 수 있는지, 어떤 입력이 필요하고 어떤 기준으로 완료를 판단할지 정의합니다.

## 1. 구현 수준

| 수준 | 정의 |
|---|---|
| `UI` | 정적 화면과 상태별 디자인이 존재 |
| `SIMULATED` | 모의 데이터로 입력부터 출력까지 동작 |
| `CONNECTED` | 외부 서비스 또는 샌드박스 API 연결 |
| `VEHICLE` | 공식 차량 SDK와 테스트 환경에서 검증 |

프로토타입의 목표는 네 핵심 기능을 `SIMULATED`까지 완성하는 것입니다.

## 2. 공통 시나리오 엔진

### 구현 방법

- JSON fixture에 시간별 차량 신호와 이벤트를 정의합니다.
- `ScenarioRunner`가 재생 시간에 따라 Zustand 상태를 갱신합니다.
- UI는 실시간 신호인지 fixture인지 구분하지 않고 공통 포트를 사용합니다.
- 발표용으로 재생, 정지, 10초 이동, 초기화 기능을 제공합니다.

```ts
type DemoScenario = {
  id: string;
  title: string;
  durationSec: number;
  snapshots: VehicleSnapshot[];
  events: DriveEvent[];
};
```

### 완료 기준

- 같은 시나리오를 실행할 때 항상 같은 화면 결과가 나옵니다.
- 인터넷 연결을 끊어도 3개 시나리오가 완료됩니다.
- 초기화 후 이전 실행의 알림과 기록이 남지 않습니다.

## 3. Drive Mood

### 구현 가능성

`SIMULATED`까지 즉시 구현할 수 있습니다. 머신러닝 모델 없이도 주행 시간, 목적지 유형, 날씨, 운전 패턴과 음악 선호를 점수화해 설득력 있는 추천을 만들 수 있습니다.

### 입력

- 누적 주행 시간
- 평균 속도 및 속도 변화량
- 목적지 유형: 일상/여행/귀가
- 날씨와 외기 온도
- 선호 장르와 최근 재생 이력

### 처리 예시

```text
여행 목적지 + 45분 이상 주행 + 낮은 급가속 빈도
→ Weekend Drive 점수 증가

60분 이상 주행 + 급감속 증가
→ Calm / Rest 모드 점수 증가
```

### 출력 및 완료 기준

- 추천 모드, 앨범 이미지, 곡, 아티스트와 한 줄 추천 근거를 표시합니다.
- 서로 다른 fixture에서 서로 다른 추천 결과가 나옵니다.
- 같은 입력에는 같은 추천 결과가 나옵니다.
- 운전 중에는 목록 탐색 없이 한 번의 추천만 표시합니다.

## 4. Drive Memory

### 구현 가능성

위치, 풍경 사진과 당시 음악을 하나의 기록으로 묶는 기능은 브라우저에서도 구현 가능합니다. 자동 촬영은 안전과 권한 문제 때문에 프로토타입 범위에서 제외합니다.

### 입력과 처리

- 현재 위치 ID와 표시용 장소명
- 풍경 기록 버튼 입력
- 촬영 시각과 공개 가능한 샘플 이미지
- 현재 재생 곡
- 5분 또는 2km 이내 기록을 같은 여행 구간으로 묶음
- 위치, 음악, 이미지 메타데이터를 IndexedDB에 저장

### 완료 기준

- 풍경 기록 시 현재 위치와 재생 곡이 함께 저장됩니다.
- 새로고침 후에도 사용자가 저장한 데모 기록을 다시 볼 수 있습니다.
- 삭제 시 이미지와 메타데이터가 함께 제거됩니다.

## 5. Car Relay

### 구현 가능성

준비된 음성 대본 또는 브라우저 STT 결과를 규칙 기반으로 분류해 구현할 수 있습니다. 실제 차량 경고등은 SDK 검증 전까지 fixture로 대체합니다.

### 입력과 처리

- 음성 대본: “운전석 앞바퀴 공기압이 낮았어요.”
- 타이어 압력, 배터리/연료, 경고 코드 fixture
- 키워드와 차량 상태를 결합해 `타이어`, `배터리`, `정비`, `경고`, `기타`로 분류
- 심각도와 다음 운전자 확인 필요 여부 계산

### 완료 기준

- 대본과 차량 신호가 하나의 카드로 결합됩니다.
- 확인하지 않은 중요 항목이 기본 패널보다 먼저 표시됩니다.
- 해결 처리 후 기본 화면에서는 사라지고 이력에는 남습니다.

## 6. Drive Guardian

### 구현 가능성

주행 습관 요약은 모의 가속·감속 이벤트로 구현할 수 있습니다. 의료 진단이나 사고 예측이 아니라 운전 습관 안내로 제한합니다.

### 입력과 처리

- 주행 시간, 급가속·급감속 횟수와 정차 빈도
- 최근 세션의 개인 기준선 fixture
- 현재 세션과 기준선 차이 계산
- 운전 중 알림은 한 번으로 제한하고 종료 후 상세 지표 제공

### 완료 기준

- 장거리/급감속 시나리오에서만 휴식 제안이 나타납니다.
- 운전 중 동일 알림이 반복되지 않습니다.
- 결과에 사용한 지표가 화면에 표시됩니다.

## 7. 지도와 내비게이션

### 프로토타입

- 한양대역–중랑천–뚝섬역 구간의 로컬 벡터 지도를 사용합니다.
- 경로는 SVG path와 진행률로 움직입니다.
- 녹색/주황색 교통 선은 fixture로 표시합니다.

### 실제 연동

- 지도 공급자의 경로 탐색 약관과 API 키가 필요합니다.
- Pleos에서 제공하는 목적지, 현재 위치, ETA 접근 범위를 확인해야 합니다.
- 지도 구현체는 `NavigationPort` 뒤에 배치해 UI 변경 없이 교체합니다.

## 8. 우측 컨텍스트 패널

한 번에 하나의 주요 맥락만 표시합니다.

```text
차량 중요 경고
> 확인이 필요한 인수인계
> 휴식 권고
> 풍경 기록 결과
> 음악 추천
> 기본 차량 상태
```

### 완료 기준

- 높은 우선순위 이벤트가 발생하면 이전 패널을 안전하게 대체합니다.
- 운전 중에는 한 줄 요약과 큰 버튼만 표시합니다.
- 정차 상태에서만 상세 기록 편집을 허용합니다.

## 9. 기능 상태표

| 기능 | 목표 수준 | 외부 API 필요 | 오프라인 시연 | 핵심 위험 |
|---|---:|:---:|:---:|---|
| Scenario Runner | SIMULATED | 아니요 | 가능 | fixture 품질 |
| Drive Mood | SIMULATED | 아니요 | 가능 | 추천 근거 부족 |
| Drive Memory | SIMULATED | 아니요 | 가능 | 사진 권한·개인정보 |
| Car Relay | SIMULATED | 아니요 | 가능 | STT 불안정 |
| Drive Guardian | SIMULATED | 아니요 | 가능 | 안전 기능 과장 |
| 실시간 차량 신호 | VEHICLE | Pleos | 불가 | SDK 권한 |
| 실제 경로 탐색 | CONNECTED | 지도/Pleos | 선택 | 키·네트워크 |
| 사용자 간 동기화 | CONNECTED | 백엔드 | 불가 | 인증·개인정보 |

## 10. 다음 구현 순서

1. 데이터 타입과 fixture를 확정합니다.
2. HMI 프레임과 Scenario Runner를 연결합니다.
3. Drive Mood와 우측 패널을 구현합니다.
4. Drive Memory와 Car Relay의 로컬 저장을 추가합니다.
5. Guardian 종료 요약을 구현합니다.
6. 오프라인 전체 흐름을 Playwright로 검증합니다.
7. 공식 SDK 문서가 확보되면 어댑터별 연동 스파이크를 진행합니다.
